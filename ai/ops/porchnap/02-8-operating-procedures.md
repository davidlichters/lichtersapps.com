## 8. Operating procedures

### 8.1 Research through Perplexity (rule since 28 Sep 2026, David)
- Any research question that needs public web knowledge (market, competitors, prices, trends, platform rules, tools, US deadlines, holidays, law) goes to **Perplexity Max**, never to the AI's own web search or helper agents, to save AI usage. Not for questions about our own files, numbers or suppliers.
- Setup: a shared Perplexity Max account from a tool reseller ("ToolSuite"), opened in the anti-detect browser DICloak, always **incognito** (shared account). Since 29 Sep every question may be concrete, including our store name, prices and suppliers.
- Script behaviour (rebuild if lost): open own tab; if logged out go to the reseller dashboard, search "Perplexity", click the tile, wait 3 s, up to 3 tries; switch incognito on and verify before and after sending; choose the best reasoning model with "Thinking" (on 28 Sep that was "GPT-6 Sol"; it found the current industry number where others did not; Deep research with it found 86 sources); wait for the full answer; save answer, report and source links.
- **Triple mode (David, 29 Sep):** ask the same question 3 times, re-run failures once, then let the model compare the three answers: agreements, every contradiction checked by a new search, gaps, a conclusion without contradictions.
- **Answer format requested in every question:** STAGE 1 (3 sentences), STAGE 2 (15 lines), STAGE 3 (all details), TAKEOVER block (decision, tasks, templates). Read only stage 1 and 2 unless the decision depends on details. A deep report is 25 to 70 KB (7,000 to 20,000 tokens).
- **Mailbox flow from another computer:** drop a JSON file `{"frage": "... Name source and date for every number.", "tief": true, "entscheidung": "which decision depends on it", "kat": "Markt|Produkt|Werbung|Lieferung|Konkurrenz|Werkzeuge|Recht|Idee"}` into the shared repo's inbox folder and push; a watcher on the Mac polls GitHub every 10 s, starts it (measured 20 s from push to start) and writes the answer back with a status table.
- Measured 28 Sep: deep research on banned Meta accounts 5 min 54 s, 196 sources; Q4 ad costs 281 s, 96 sources; normal search 69 s, 21 sources. Same research by screen clicking had cost about 25 AI calls with screenshots.
- **Gotchas:** run questions strictly one at a time (parallel tabs share Perplexity's draft field and incognito switch: 54 of 189 runs failed until made serial); never more than 2 to 3 own questions at once on a shared account ("Unable to start session"); a mass test of 14 reseller tools in 16 minutes triggered the reseller license lock for a night; when logged out for weeks: in DICloak delete perplexity.ai site data under chrome://settings/content/all FIRST, then quit DICloak fully, reopen, open the profile, tile works on the third try (6 Nov). Always write "for a US shop, customers in the USA" in the question or Perplexity plans for Germany. Check before asking whether the same question is already answered or queued. "Finished" in the status table only means an answer file exists, not that anyone used it. When extracting the TAKEOVER block, take the last line that is exactly the heading, not the first occurrence of the word (the word also appears in the question; 44 of 61 answers had unseen decisions because of this).
- **Perplexity is a source, not proof.** Every number is [RATE] until checked at its source or in the courses. Perplexity's takeover blocks use industry values (for example pause at 58.50 CPA) that are above our 47.01 break-even: never copy them unchecked. For narrow creative or niche-price questions it almost never has a real number (no published conversion rate for Christmas dog beds at 59.99/69.99/79.99; industry CVR 1.53 to 3.27 % only); then run your own test.
- Useful answers we got: hit rate per product test (Meta, USA, about 150 USD) has no measured source, vendors claim 5 to 20 %; always compute with 3 % and 5 %. USD payouts save a German Shopify store only 0.5 % (2 % conversion vs 1.5 % multi-currency fee) and only on Advanced. Meta "Test events" is not a sandbox and native Shopify CAPI has no test code field; only the browser Purchase counts as proof. An empty review widget has no proven conversion damage vs no widget.

### 8.3 Shopify procedures (learned the hard way)
- **Read store state without login:** `https://<domain>/meta.json` (store name, country, number of published products, ships_to_countries, Shop Pay card brands), `/products/<handle>.js` (prices in cents, variants), `/products.json`, cart via `/cart/add.js`, `/cart/shipping_rates.json?shipping_address[zip]=73301&...` (empty cart afterwards with `/cart/clear.js`). Use an iPhone user agent.
- **Cloudflare rate limit:** 3 quick requests in a row can make Shopify answer HTTP 429 "Verifying your connection" on every page for about 45 to 60 minutes. At most 1 request per minute from automation, never loop over URLs without pause. Check the HTTP code before reading any text result (a 429 page contains none of your search words, so "not found" looks like "fixed"). Wait 45 to 60 min and re-measure before escalating "shop down". When curl is blocked, the Admin API shows the same state.
- **Change the store without the theme editor (Admin API):** policies via GraphQL `shopPolicyUpdate(shopPolicy:{type: REFUND_POLICY, body:"..."})` (takes type plus body, never id); read the current body first, replace exactly one occurrence, keep a backup. Navigation via `menuUpdate` (menus are not theme files, no publish needed). Product description, image alt text and SEO title/description sit on the product (`productUpdate(product: ...)` in API 2025-01, not `input:`). Pages via `pageUpdate` (one change fixes every place the page renders). A single theme JSON switch via the Asset API: GET `themes/<id>/assets.json?asset[key]=templates/product.json` (curl needs `--globoff` for the brackets), confirm the key appears exactly once, back up, PUT. Theme files can also be written from an admin tab with `themeFilesUpsert`; a value off the range step of a setting (72 instead of 70) fails the whole file.
- Text may live twice: once in the product description and once in a theme section; check which body actually contains the sentence. Re-measure with a cache buster (`?nocache=<time>`), CDN shows the old version up to a minute.
- **Theme safety:** duplicate the theme before any big change. `shopify theme duplicate` once produced a copy with an empty layout file and empty settings schema: never publish a copy before pulling it fully and diffing against the original. Before any push to live run `shopify theme list`; an ID from an old note can be outdated (one push went into an unpublished theme). Running `shopify theme list` without login opens a browser login and can steal the screen.
- **Hide a variant** per channel (Variants > Publishing > Manage publishing) instead of deleting it.
- **API tokens:** a custom app token created for "read orders" actually carried 101 scopes, 74 of them write (prices, themes, customers, policies). Always check the scope list of a new token (a fresh client-credentials exchange returns it). Client-credential tokens renew every 24 h automatically; "token expires tonight" alarms were false for 5 days. A section without visible block stays invisible even if the page update succeeds (contact template had main-page disabled).
- Orders via GraphQL with `createdAt` and `totalPriceSet` (no date filter; it broke on time zones) give a reliable "orders today / profit today" without the ad account.

## 9. The automation loop ("Takt") and what it taught us

- A Mac launch agent started a headless AI run every 5 minutes (max 18 minutes each): 9 to 10 "chief" runs per hour (strongest model), 2 research runs (Perplexity, target 100 questions per day from 3 Oct), 1 improver run every 2 hours, creative runs on demand. Each chief run checked a "money ladder" of 6 stages top-down (1 money blocked: checkout differs from page/ads, shop down, ads off although due, account or payment blocked, order not passed to supplier; then supplier, shop fixes, yes-list, escalation) and worked on the first hit. Results were "world change", "escalation with time" or "internal". An "internal lock" forced at most 1 of 4 runs to be internal. Escalations reached David via a WhatsApp poll group and reminders. Questions needing a human went into a yes-list with max 8 slots.
- **Hard limits of every automatic run:** never send any message, never spend money, never change account settings, never publish to the live theme; prepare and ask instead.
- **What went wrong (all measured):** the loop was dead for 49 hours (95 of 101 runs "401 API key invalid" from a stray environment variable) and reported it as something else; two runs ran at once because the lock check `test -f` is not atomic (use `mkdir` as lock); a run deleted a similarly named foreign file together with its lock (only delete the exact named file); the same blocker was written as new lessons 5 times in a row; nine yes-lines were created separately for one root cause; escalations were scheduled at 01:49 with zero buffer inside night rest; stale summaries made runs repeat already-solved items; a 7.6 MB log was parsed whole and burned context (read with tail, never whole); the loop silently consumed Timo's personal AI quota because the account rotation included his login. Several chief runs wrote directly to the live store via Admin API without a yes-line, against the rule; on 9 Oct writes were paused pending David's decision.
- **Core lesson:** a loop that cannot reach money (ads, accounts, sending) produces reminders, not revenue. Measure output as "what changed outside our notes". Before re-escalating, check whether the item is already live; old yes-lines were often silently fulfilled by another change. A fault that appears every hour unchanged is an alarm after 24 hours, not a log line.

## 10. Product research by "leak scan" (late October 2026)

- Idea: ecom creators accidentally show their Shopify dashboards, browser tabs or bookmarks in TikTok/YouTube Shorts. Download videos by hashtag (#ecom, #ecommerce), OCR the frames, extract store names and products, then verify.
- **Verification is everything:** a store name read in a video is only a hint; it becomes a candidate only if the Meta Ad Library shows active or past ads for that store or product. Leaks can be staged (one account showed identical prices and running order numbers across two stores, 380 numbers in a minute). 87 hits from 1,979 videos came from only 14 accounts, 39 from one tool vendor's demo stores: count accounts and verified candidates, not hits. Real leaks are short, small and accidental in the frame (a tab, a bookmark, a lock screen); anyone deliberately showing a product is advertising (tools, apps, agencies, tutorials); judge by bio and description, image share alone does not separate them. Stores selling info products (supplier lists, AI toolkits, e-books) are not product winners. Result of the filter: 10 of 112 hits real.
- **Phase check:** leaks often show old winners. Judge phase only by active and new ads, not by words like "clearance" (Timo: "clearance are sales words"; one store was clearing a faulty batch while normal ads ran). Take the role model, phase and store link from the store that advertises the product TODAY (search the Ad Library by product word), never from the leak store (one leak store had switched to gloves by then).
- Operation: at most 3 parallel downloads (10 to 12 got TikTok to block, and the scanner marked 1,470 of 1,571 videos "done" in 7 minutes: a run much faster than usual is a fault); retry transient errors, pause 5 minutes after 5 in a row; YouTube Shorts need a 720p-plus format for readable tab text; run heavy jobs at low priority (8 workers made a PC unusable).
- Product verdict sheet (29 Oct): color-changing foundation YES (contribution 43.69 at 49.00, 11 advertisers); 4-in-1 travel dispenser RE-MEASURE (landed cost missing, worth it only up to 13.32 USD, about 140 ads, sold at 34.99 to 39.99 by the current advertiser); steam cleaner NO (markup 2.51 below 3.0, no 110 V device). Rule: markup (price / landed cost) at least 3.0.

## 11. Curlmoon (David's own store, from 1 Nov 2026)

- David, 1 Nov: "This store I do alone." Separate Shopify account, separate brand, never written into Timo's store. Separate Facebook profile, business portfolio and ad account (David, 3 Nov: a ban on Timo's side must not take Curlmoon down). The Shopify connector of the AI is attached to Porchnap; never use it for Curlmoon.
- Product: "Curlmoon Nest", a calming/donut dog bed. Market winners measured: mrfluffyfriend.com (131 ads) and Muddy Mats Cloud K9 (79+ ads for "anxiety dog bed" since 22 Jul). Supplier John quoted donut beds 40 cm 10.02, 50 cm 11.86, 60 cm 14.52, 70 cm 18.65 USD (2 Nov).
- Built as a mobile-first preview on GitHub Pages from 12 competitor product pages, then reviewed against all repo rules until no finding remained. Quantity tier only "2 beds minus 10 %" (67.3 % margin at the quoted prices; 15 % would give 65.7 %, below the 67 % floor). Placeholder reviews only in the preview with a visible PREVIEW banner and noindex; the real store follows the lawyer list.
- **Prices and cost-per-purchase thresholds (current since 2026-11-06 12:0x):** before the first ad impression David said "decide yourself", and all sizes were raised by +10 USD: 16" **54.99** / 20" **59.99** / 24" **69.99** / 28" **79.99** USD; 2 beds 20" **108.00** (54.00 each, saves 11.98; the discount was checked in the real cart). Reason: course "slightly higher if it's tighter" (lesson "Preisgestaltungsstrategie"), contribution of the 20" rose from 62.4 % to 66.4 % after refunds, and with 0 impressions no test was disturbed. Numbers for the 20" at 59.99: goods 11.86 per bed, fees 5.83 %, contribution **44.63 USD** (74.4 % before, **66.39 % after 8 % refunds** [GUESS on the refund rate]); target cost per purchase as Ads Manager shows it **37.50 USD** (33.47 with refunds), **emergency brake 75.00 USD**. **Hold the price until 20 purchases** (rule D17), and change nothing in the first 48 hours (D5). If the full test brings 0 purchases, the price is only one of several possible causes. Source: David's price file for Curlmoon, 2026-11-06; the threshold derivation is in https://lichtersapps.com/ai/ops/product-testing/01-contents.md section 7.
- **Older, replaced on 2026-11-06:** prices 44.99 / 49.99 / 59.99 / 69.99 USD and 2 beds 20" 90.00 (45.00 each, saves 9.98; measured live 2026-11-06 before the raise), and the thresholds for 49.99: 29.60 USD cost per purchase / 59.20 USD brake (26.23 with refunds). The plan then was to keep 49.99 until 20 purchases and test 54.99 afterwards; it was replaced by the raise above. Do not use these numbers.
- Measure prices on the live store, not in local copies (a copy said 89.98, live was 90.00; both are the old 2-bed price before 2026-11-06, today live is 108.00). Mobile LCP of the preview 1.5 s on slow 4G. Warm-up per D2.

## 12. Working rules between David, Timo and the AI

- The AI decides content (what to buy, test, budget, send) and prepares everything; only humans press: log in, buy, pay, publish budgets, send. Shopify settings, products, texts, pages, theme and installed apps: AI may change freely (Timo, 3 Oct evening); prices and anything costing money: ask first; deleting: ask first. Meta settings: only after a yes for that exact change, one change at a time, never the same button twice in a row (account bans), read to verify instead of clicking again; stop at any login, captcha or security page.
- Never change profiles (picture, name, status) in any app, even on urgent request (Timo, 23 Sep).
- WhatsApp: only chats marked "(Supplier)" and their groups; never friends.
- Ask in one line with the finished proposal so "yes" suffices ("Raise ad 1 from 10 to 15 USD/day. Reason: 2.10 USD per sale, best in account. +5 USD/day. Yes?").
- Every number with its denominator, period and source in the same sentence; "denominator unknown" is a finding. Counted things: delivered, not sent. Under 30 cases it is an observation, not a finding. Documents do not cite documents: check the source.
- A rule from Timo or David entered the playbook only after the course judge found a lesson; struck tasks go to a "declined" list and are never proposed again (BM3 task was repeated 8 times on 3 Oct).
- Each human task names the purpose first ("so that ...") and the click path from the screen the human sees.
- Mindset (Timo, 29 Sep): "David and I will get rich, statistics don't matter." Never quote failure rates of others; only own measurements decide which lever comes next. If the plan cannot reach the goal, say so as a task with a solution.

## 13. Lessons learned, the full list

1. Judge products only on the last 7 to 14 days, never on all-time sums.
2. A goal number about a person counts only when that person said it; templates are not facts.
3. Never assume EUR; write USD in every line.
4. Count delivered things, not sent ones; under 30 cases is an observation.
5. A true sentence can kill a sale ("you can do this yourself in two minutes"); if it is true, change the offer.
6. In a chain of tools, first look at what the last link actually received (speech recognition turned German into Icelandic).
7. Before any scheduled job, run it once by hand and read the log; the CLI login is separate from the app login.
8. Measure before shortening a step: the domain had pointed to the shop for 2 days while the plan still listed it as a task.
9. After every value decision, search and replace across all files; a correction in one file lives on in the others.
10. Compute roundings and statistics with code, never in your head (bundle 74.25 vs 74.24; 173.47 vs 173.41).
11. A 0 in purchases can be password protection or a wrong pixel; check both before the first dollar.
12. Kill by spend threshold per purchase count, not by CPA from few purchases; compute the false-kill rate first.
13. Before comparing with a course number, check the formula: course "break-even" = list price minus goods; ours also subtracts fees.
14. Course prompts state their audience in the first sentence ("domestic suppliers", "high-ticket"); check it against our model before copying.
15. Customer answers only from what the page says (washability and breed fit were not documented, so "we're confirming").
16. An app called "free" often is not (upsell app free tier capped by revenue; Apple/Google Pay buyers never see post-purchase offers).
17. A course minimum for 9 videos vs 10 to 20 creatives: write down when you deviate.
18. A poll vote is no proof (a "test purchase done" vote stood against 0 orders); measure the source.
19. A sentence about a state is not a state: read the status before claiming "stays off" (a cross-poster had been re-posting someone's TikToks for days).
20. Before saying "no reply from supplier", verify the chat reader opened the right chat and read the sender line (it twice showed another chat; quoted replies mix old and new text).
21. Supplier, legal and review promises: write every page and policy together and read them side by side.
22. Things that are fixed by humans in their own chat must be mirrored into the shared task lists at once, or automation keeps escalating a solved item.
23. Every rule needs a trigger and an action; "be more careful" is not a rule. A rule that fired 3 times becomes a tool or checklist step.
24. Whoever names things first fixes the names in one file; three naming systems for the same ads caused confusion.
25. The deciding failure: being slow. Launch, then improve; prepare everything to the last button so the human only presses it.
