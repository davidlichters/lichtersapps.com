## 6. Research: Perplexity bridge, ToolSuite adapter, Nano Banana, course judge

### Why

David, 2026-10-03, fixed rule: everything Perplexity can do, Perplexity does. Web search inside Claude is blocked in settings. Questions that need no local files (market, prices, rules, platforms, competitors, tools, tax, deadlines) go to Perplexity, so Claude usage is not spent on research.

### Perplexity bridge

Access: a shared "ToolSuite" group-buy account (Perplexity Max) that runs only inside **DICloak**, an anti-detect browser manager, which opens profile "Dashboard" in its own Chromium ("Gins Browser"). DICloak's open API is disabled for member accounts and its debug port does not listen, so the bridge uses AppleScript `execute javascript` into the Gins Browser (Allow JavaScript from Apple Events enabled there, 2026-09-28).

**Script and folders:** the full call is `node ~/perplexity/frage.mjs [--tief] "question"` (short: `frage`). The login runs through the ToolSuite tile on the ToolSuite page inside profile "Dashboard"; frage.mjs clicks it itself. Answers land in `~/perplexity/antworten/` (file name carries second and model); answers shared with Timo's PC in `~/timo/wissen/perplexity/`; the inbox state in `recherche/STATUS.md`. **Parallelism (David, 2026-09-28):** up to 20 runs at the same time, each in its own tab that it closes afterwards; only one run may log in through ToolSuite at a time (tested with 3 parallel questions, no mixing). The continuous queue runner allows **MAX 6** at once (raised from 4 on 2026-09-29). In practice keep fewer: 12 to 17 parallel runs made 70 % fail on 2026-10-03 (step 7 below). Source: AI memory file "perplexity-skript".

**Commands:** `frage "question"` (normal, max 12 min wait), `frage --tief "question"` (Deep Research, max 40 min), `--lesen` (save answer of the open tab), `--modell "<name>"`, a queue runner over a text file (one question per line, `tief:` prefix = deep; finished lines move to a done file with the result path; stops on first failure).

**Flow of one question (each step verified, not assumed):**
1. Open a new tab (globally max one new tab per 3 s, because 12 to 15 tabs at once twice deleted the extension's license key).
2. Confirm incognito: page text must show "You're incognito", else turn it on. Without confirmed incognito, nothing is asked.
3. Confirm model: default "GPT-6 Sol" with "Thinking" (model test 2026-09-28: 10 models, same numbers question; Deep Research with Claude Opus missed the current figure, GPT-6 Sol found it normal and deep, deep with 86 sources; wrong vs right: the current Meta pets CPM was 16.27 USD (Triple Whale, 2026-08-18); Claude Opus deep gave 9.56 USD instead, a full-year 2025 all-markets figure; source: model comparison result file 2026-09-28). GPT-6 Sol is the default also for Deep Research. "Grok 4.7" as cross-check via `--modell "Grok 4.7"`.
4. For Deep Research: fake focus (`document.hasFocus` returns true, fire focus/focusin), type "/" into the empty field, wait until the mode menu is open (checked from node every 0.4 s), press Enter to pick "Deep research". Enter without the open menu submits an empty question (happened 2026-09-28).
5. Insert text with a paste event (execCommand does not reach the editor in a background tab) and click "Submit".
6. Verify submission: a thread view ("Answer" and "Share" present, field empty) or URL `/search/<id>`. "Submit clicked" is not proof: on 2026-09-28 four questions stayed in the field because the page jumped back home.
7. If Perplexity shows "Unable to start session" (shared account at its concurrent limit; 70 % of runs failed 2026-10-03 18:30 to 19:25 with 12 to 17 parallel runs), wait 10 s and click again, up to 16 times.
8. Wait for the "Helpful" buttons, save answer plus attached report with sources to a timestamped file (name carries second and model; parallel runs once overwrote each other), close the tab. Never click "Related" suggestions (they now look like report buttons; clicking posts a follow-up question).
9. Tab crashed ("Aw, Snap"): reload once. Every run goes to a JSONL log.

**Verify Deep Research really ran:** in the tab, `fetch("/rest/thread/<id>")`: `user_selected_model` is `pplx_alpha` for Deep Research, but only once status is `completed` (while pending it shows `turbo`).

**Known traps:** a leftover "/" survived reloads because Perplexity stores the draft in sessionStorage `pplx.activeQuery`; clear that key. Without real focus the "/" menu never opens.

**License key:** the ToolSuite extension shows "Enter your license key" on every page when its storage is empty. A watcher re-enters it automatically (every 2 to 15 s); after 3 rejections in a row it waits 10 minutes. Each activation sends a new device fingerprint and ToolSuite deletes keys on `device_blocked`, so mass activations are dangerous.

**Cold start / restart:** DICloak clears the profile cache on every open (its cache file timestamp matches the browser start to the second), so restarting profile "Dashboard" IS the cache clear. Daily restart 07:07, 13:07, 19:07. The "Open" button is clicked through the macOS Accessibility API (AXPress) from a launchd helper that runs `/usr/bin/osascript`, because macOS grants Accessibility to the "responsible" binary; granting `/usr/bin/osascript` once makes it work from chat, cron and launchd. Traps: the window may be on another desktop (find via AXMainWindow); after a DICloak restart the window is 1,009 px wide and the "Operation" column with the buttons is off-screen (drag the bottom scrollbar right); the button label carries a private-use icon character (" Closed"), strip U+E000 to U+F8FF before comparing; the "Close profile" dialog ignores AXPress; never open the neighbouring "Rankerfox" row. If DICloak asks for a login, stop: only David types that password. If all automation fails, fix it yourself by hand in the app immediately (David 2026-10-25: never ask him to say "repair Perplexity").

**Triple research:** the same question 3 times to the same model, then the model compares the three answers, checks every contradiction with its own search, writes a contradiction-free conclusion. An "exclusive" wrapper waits until no other run is active, takes the single slot, runs N times plus comparison.

**Mailbox for other machines (2026-09-29):** any chat (also Timo's PC) drops `recherche/eingang/<date>_<keyword>.json` into the shared Git repo: `{"frage": "... name source and date for every number", "tief": true, "entscheidung": "which decision depends on the answer", "kat": "Markt|Produkt|Werbung|Lieferung|Konkurrenz|Werkzeuge|Recht|Idee"}`. A Mac watcher runs `git ls-remote` every 10 s (no pull, no model), starts the question ahead of the queue (20 s from push to start, measured), and commits the answer to `wissen/perplexity/`. Every answer has 4 levels: LEVEL 1 (3 sentences), LEVEL 2 (15 lines), LEVEL 3 (all details), TAKEOVER (decision, tasks, templates). Read only 1 and 2 unless the decision hangs on 3. Since 2026-09-29 every question may be concrete (business names, suppliers, prices), because all chats run incognito.

**Status 2026-11-06:** logged out for a while (three attempts via the tile failed); fixed at 16:15 by clearing data and David restarting DICloak.

Only one run may click the login tile at a time (shared lock with Perplexity). Adspy recipe tested 2026-09-29: 40 ads for "dog bed" with advertiser, country, runtime, reactions, comments, text, products, links.

**Incident 2026-09-29:** opening 14 tools in 16 minutes probably triggered ToolSuite's sharing detection; from then every tool and Perplexity showed the license prompt [GUESS: "probably ourselves"]. Hard limit since: max 5 tool openings per hour, never a mass exploration. An earlier "36 of 44 logged in" was wrong because the check looked only at URL and text length.

## 7. Screenshots and page checks

- **Phone screenshot of any URL:** headless Chrome with a throwaway profile and random debug port; CDP `Emulation.setDeviceMetricsOverride` 390x844, DPR 2, mobile true; iPhone Safari user agent; navigate; wait 3.5 s; log innerWidth vs scrollWidth (horizontal overflow check) and scrollHeight; `Page.captureScreenshot` clip 390 wide, height up to 2,400 (or given), `captureBeyondViewport`. Kill Chrome after. Gotcha: each run leaves a `prof-cdp-<pid>` folder; clean them up.
- **390 px rule:** nothing goes to a customer without being looked at at 390 px. Origin 2026-09-11: David had to write ten messages to fix one page; they were four avoidable error classes, 3 of them layout errors visible in 20 seconds on a phone.
- **Page acceptance checker:** carries the design rules in code (so not reading the design file does no harm) and requires proof of viewing: `--gesehen 390` records the sha of exactly this file version at exactly this width; any change invalidates it. Modes: sales page (price in headline, call to action, short summary required), `--pflichtseite` for imprint/privacy (no sales rules, but design, contrast, age leaks, self-sabotage and phone-view proof stay), `--nachkauf` for the post-purchase page. Exit 1 on any failure. Never sends anything.
- **Self-sabotage check ("Selbstschuss", 2026-09-11):** finds true sentences that tell the reader they do not need us. Origin: "You can look up each of these names yourself in two minutes" sat right above a 79 EUR/month price. Runs in the stop hook on every customer-facing text. File: `werkzeug/selbstschuss.mjs` (`node werkzeug/selbstschuss.mjs seite/index.html`), called from `.claude/hooks/nach_runde.sh`. It flags wording that makes the problem look small, cheap, fast or do-it-yourself ("können Sie selbst", "in zwei Minuten", "einfach", "öffentlich zugänglich", "auch ohne uns"). A hit may stay only with a written reason in the line before: `<!-- selbstschuss-ok: reason -->`. The hook has a `--selbsttest` that builds pages with known errors and passes only if both checks fire (added the same day, because the hook had silently done nothing since the day before). Full rule: working-rules, sending messages ("a true sentence can kill the sale").
- **Human-text gate:** one command for every text a stranger will read (profile text, bio, subject, signature): all such texts live in one folder and all pass through all checkers. Origin 2026-09-12: a WhatsApp profile text reached David unchecked because the checkers only knew one file.
- **Rounds with a criterion ("runden", 2026-09-22):** David wanted "50 rounds" to deliver something he sends immediately. Root cause: one message took 4 versions and 100+ rounds because each round asked "is it better now?", which nothing can fail. Fix: a scoreboard of binary checkpoints, each backed by a real past mistake. One round fixes exactly one checkpoint and logs its id. Three empty rounds in a row = saturated, stop. A new mistake becomes a new checkpoint.
- **Simulator screenshot:** `xcrun simctl io <device> screenshot`, shrunk; every image is checked for Apple's "Sign in to Apple Account" sheet (never type into it; restart the simulator).
- **Watching a video (TikTok, Reel, Short):** never judge from title, hashtags and likes. Open a web downloader page (ssstik, snaptik and similar), paste the link, play it, capture about one frame per 0.1 s, read frames in order; describe what happens cut by cut before any verdict (David 2026-09-14). For bulk: download with yt-dlp, `ffmpeg -vf "select='isnan(prev_selected_t)+gte(t-prev_selected_t,0.5)+gt(scene,0.08)'"` (one frame every 0.5 s plus every cut; +30 % frames, catches short inserts), then OCR.
- **OCR without a model:** macOS Vision (`VNRecognizeTextRequest`, accurate level, language correction, en-US and de-DE) writes `<image>.txt` next to each image; Windows: built-in `Windows.Media.Ocr`, two-pass (read small; re-read 2x magnified only if a shop hint appears, because "name - Shopify" in a tab is only readable magnified).

## 8. Store building tools

Rules for store building itself are in `ourrules/shop-building.md`; legal answers in `ourrules/legal.md`. Tools:

- **Store clone skill ("shop-nachbauen", 2026-10-03):** one prompt "Rebuild our store 1:1 in the look of <URL>". Procedure: collect the target's values (layout order, fonts, colors, spacing, blocks) by reading the page, build into an unpublished theme copy, check at 390 px, compare screenshots side by side, publish yourself, run a "purchase brakes" pass, send David the comparison image. First run: Porchnap in a competitor's look, live 2026-10-03 22:05.
- **Publishing Shopify themes:** the claude.ai Shopify connector can write files only into unpublished themes and cannot publish ("making a theme live must be done manually"). The Shopify CLI can: `shopify theme list --store <store>`, `shopify theme publish --theme <id> --store <store> --force`. Login is a device code David confirms once (1 minute); when it expires the CLI prints a new code: redirect output to a file, never pipe through `sed` (buffering hides the code). Every change: copy theme, check 390 px, verify the live theme's updatedAt did not change since copying (someone else edited?), publish, re-measure live.
- **Curlmoon preview builder:** the second store was first built as a static preview on GitHub Pages from the strongest parts of 12 competitor stores: a Python builder assembles HTML part files (offer, band, reviews, short reviews, FAQ, "for whom", guarantee, sizes, comparison, benefits, closing), plus a phone-view check and a speed check. Preview pages carry a placeholder banner; stars there were placeholders. Then a template builder converts it into a Shopify product template JSON (sections and blocks, custom liquid for subline and three feature-then-benefit bullets).
- **Review section builder:** builds a reviews section, a star-row snippet and a reviews strip as Liquid from a JSON pool of reviews of the same product: text verbatim (only edge whitespace trimmed), name as at the source or "Anonymous", buyer photos as large webp plus 200 px square thumbnails, order: pinned top, pinned bottom, rest as grown. Sources were a competitor store's public Judge.me reviews and AliExpress buyer photos. Legal basis and limits: `ourrules/legal.md` (lawyer answers 2026-11-02 and 2026-11-05: selecting reviews is allowed, below 4.7 average remove the most harmful bad ones until 4.7; source credited small at the bottom of the store, never in ads). The automatic review collector was locked until a lawyer answer (2026-11-06). David 2026-11-02: the real store gets only real reviews; preview placeholders stay marked.
- **Product media collector ("Sammler", 2026-11-06):** input a product sheet; collects photos and videos of that product from competitor stores found in the Meta Ad Library. Rules in code: public shop pages only by plain curl, no browser disguise; on bot check, 403, 429 or 503 the domain is locked forever (no retry, no other sender); never call review services; photos inside review blocks are customer photos and are locked; supplier images with prices are never released; duplicates by sha256, crops and re-encodes do not count; theme sample images inside scripts do not count; "same product" stays null until a human or eye check confirms. Nothing deleted, rejects go to a rejected folder with class and reason. Acceptance target 100. **Status 2026-11-06 [MEASURED]: failed** on a new product (42 of 100, and the image set mixed 3 different lamps), worked only on the calibration product; ~26 of 94 images carried foreign text or seals ("BOGO", "Therapist Approved"). Next step was a reference-image comparison and a "foreign text" class.
- **Product gate / calculator:** a product passes only with at least 70 % contribution margin and a price of at least 60 USD (2026-11-06). 70 % means goods at most ~16 % of price after fees (1 minus 5.83 % minus 8 % minus 70 %). This is our own threshold, stricter than the course (which also names 60 %). On 2026-11-06 only 1 of 15 candidates passed.
- **Ad rules as code:** pure function: readings (spend, CPC, link CTR, sessions, carts, checkouts, orders, hours since start, revenue, per-ad stats; missing = not read, never 0) plus a trial config (ids, thresholds, phases, verdict texts, all in JSON, none in code) give the verdict. Tested against 36 written cases. Thresholds for the Curlmoon trial: 37.50 / 75.00 (2026-11-06). Rules themselves: `ourrules/meta-ads-playbook.md`.
- **Campaign build script:** builds the Meta campaign as a script from the ad sheet; dry run matched the existing ad list (24 differences explained), never goes live without a standing yes from David.
- **Store watcher (Curlmoon, 2026-11-05):** every 30 min, no model, read only: in David's Chrome finds the Ads Manager tab and the Shopify admin tab, reads campaign/ad set/account status, spend cap, ads, insights (via the Graph API from inside the logged-in tab) and the last 20 orders (fetch from the admin tab); alerts at level 2 only on a stop or a purchase, each alert once. Shopify once answered 403 "Verifying your connection": one normal tab reload fixes it, never bypass. Off file and end date built in.
- **Shop target checker (Porchnap, 2026-10-03):** checks the live store against the playbook (prices, shipping, US only, tracking app) without a cart. **Live check:** fetches the public product page and `/products/<handle>.js`: title, price, available, variant count, review count, star average.
- **Shopify page text to HTML:** converts the "text for the page" section of a Markdown page into inline-styled HTML; exits 0 only if the HTML without tags equals the source text (no silent edits). A "click path" builder makes one HTML page with one row per admin step, a button into the right admin URL and copy buttons for values; every value must exist verbatim in the source, else abort.
- **Meta bulk import CSV builder:** reads ad texts from the input sheet (never retyped), budgets left empty (human decides), status PAUSED. Column names were a [GUESS] from memory.

## 9. Product hunting: leak scan, shop finder, ad library, media collector

- **Shop finder (2026-10-28):** from a shop name seen in a video, find the real Shopify store and all products. Generates domain variants: the exact domain if one was read; else word-joined, hyphenated and first-word cores with .com .store .co .shop .co.uk .de .eu; prefixes try/shop/get/the/wear + core .com; `<x>.myshopify.com` for internal handles like "abcdef-gh"; and a hyphen before common end words (osxbeauty -> osx-beauty.com, the first real find). For each candidate GET `https://<domain>/meta.json`; a Shopify store answers with `myshopify_domain`; then `/products.json` lists all products. 10 s timeout each.
- **Leak scan (David's idea, 2026-10-28):** e-commerce creators often show their store for a few frames (Shopify tab "name · Shopify", order notifications, dashboards, address bar). Collect video links (TikTok: a script injected into a logged-in TikTok page scrolls search/profile pages and stores links in localStorage, slow pace so the account is not flagged; YouTube Shorts: `yt-dlp --flat-playlist` on `/hashtag/ecom/shorts` and `/hashtag/ecommerce/shorts`, 1,721 unique on 2026-10-29), download, extract frames (every 0.5 s plus cuts, max 60 s of each video), OCR, match patterns, run the shop finder. A name counts only from 2 frames; OCR misreads (Seram/Sereno for Serano) are normal. TikTok lists show only ~170 to 250 videos; profiles give more; the post date is in the TikTok video id (upper 32 bits = Unix seconds). Max 4 workers (8 froze the PC). No model, idle priority. Found 2026-10-28: four real stores including one with 4,100+ orders.
- **Real or staged (Timo, 2026-10-29):** a real winner is visible only briefly, small and by accident. "If the product were really a winner, nobody would post it on purpose." Flags: tool/agency/course sellers in bio, descriptions that present a product, store visible in >60 % of frames, many stores per account (one account showed the same order counter in several "stores").
- **Ad Library phase:** a script injected into the Meta Ad Library (search with `active_status=all`, then `active`) returns hit count and per ad status, runtime, page, text start, target domain; a classifier says running, sell-off, quiet or over. The page must be visible (hidden it renders nothing and returns 0 hits).
- **Video watching and frame reading:** section 7.

## 10. Knowledge builders: course library, knowledge book, ecom site, /ai

Pipeline that turned ~118 hours of purchased video courses into the text behind `/ai/ecom/`:

1. **Download and transcribe** each course video; whisper-cli on Metal. Never two whisper runs in parallel: the first crashes (rc 134 "failed to process audio"). Subtitles where available (yt-dlp subtitles only, VTT to text with a [hh:mm] mark every minute). Disk guard: paused downloads resume when >40 GB free.
2. **Chapter map per video** (cheap model, Haiku): title, summary, topics from a fixed list identical for all courses, English search terms, chapters with second, concrete facts with second. The transcript stays the source; the map is only a signpost. Two workers in parallel with a lock folder.
3. **Build lesson files:** one file per video: header, chapters, facts, then the verbatim transcript with [mm:ss], screen text (OCR of screenshots) with image path. Documents (PDF, DOCX, XLSX) become lesson files without a model (XLSX read from the zip's XML). Index, topic pages, full-text file for grep.
4. **One library by topic, not by course:** lessons sorted under topics, file names neutral, the course named only in the last line. A checker fails if a single transcript word is missing or out of order (mutation-tested on 5 defect classes). Status 2026-09-27: 490 lessons, 118 h, 1,263,235 transcript words checked, 0 missing.
5. **Statements layer:** a model extracts every checkable statement per lesson (number, rule, setting, step, tool, warning, with condition); kept only if its quote appears character for character in the lesson (timestamp taken from the find position, not from the model); a second model checks each German line against its quote (condition, restriction, modality, subject, superlative) and replaces deviations. Per-question overviews: positions with lesson, [mm:ss], year, verbatim quote; every quote must come from the supplied list (else retry); a second model checks again.
6. **Prompt index:** all prompts from the courses collected verbatim, indexed by purpose with German and English keyword regexes (about us, refund page, shipping page, product description, product image, domain name, CSV reformat, niche ideas, target group, pages, compliance, product upload...). A hook injects the matching course prompt when a task fits; David's rule: use the course prompt verbatim with placeholders filled, never invent one.
7. **Knowledge book (2026-10-30), English, own words**, so it can be shown without course text. Stage 1 units: per lesson a cheap model extracts every unit of know-how, a second pass adds what the first missed; units sharing 12 words in a row with the lesson are rephrased, never dropped; prompts kept complete as improved paste-ready versions. Stage 2 chapters: per topic an outline (Sonnet), every unit assigned to a section, sections written, then every unit id is checked; a unit the text does not cite is appended verbatim. Stage 3 plain: every section rewritten for a beginner with ADHD plus "in short" lists, ids checked again. Stage 4 build: technical tree for AI and a two-part PDF. "Zero loss beats polish" (David: "rather too similar than something lost"). Runs only 23:30 to 06:00 because it shares David's Claude account.
8. **Ecom website and /ai deep files:** builders turn the book into `lichtersapps.com/ecom/` (readable) and `/ai/ecom/deep/` (technical): source ids removed, course and person names replaced by neutral labels, course URLs removed, long dashes removed; a check aborts the build if anything forbidden survives. Lawyer 2026-11-07: public and indexable is allowed.
9. **Course PDF:** pandoc to HTML, headless Chrome to PDF in parts of max 1.5 M characters (Chrome chokes above), then pdfunite.
10. **Quality test:** 10 questions, fresh model each, strict reviewer separating errors from hints. Result 2026-09-27: data complete, but paraphrasing slipped (added "only", dropped "probably" and conditions, one side of a contradiction missing); best round 4 of 10 error-free.
