6.19 Testing methodology and the CRO cycle

When to test and what to expect

  • Do not recommend A/B testing by default when the brand likely lacks enough traffic. Label obvious, low-risk changes as a "fix" rather than a "test" [L0886.007].
  • In the first audit output, hero positioning, risk reversal and comparison modules should each be labeled a test only when traffic supports it. Otherwise, label them fixes [L0886.021].
  • Low-traffic stores can run fewer tests at once [L0572.012].
  • Do not run A/B tests with very small traffic. Splitting 20 sales into 10 and 10 gives results that are not statistically reliable. Beginners should skip formal testing at this stage and fix obvious problems first [L0390.012].
  • Results from low-traffic stores have low statistical significance and should be treated with caution. Large platforms such as Amazon test nearly everything, but a small store should test as often as its traffic allows and should not overread small differences [L1077.052].
  • Conversion rate optimization tests need enough traffic for a statistically reliable sample. With low traffic, such as outside peak season, a clear winner can still appear, but small differences are not trustworthy and should not be acted on [L0999.021].
  • A large change, such as 40 percent, can be acted on even with limited data. A 2 percent change is too small to trust [L0999.022].
  • Low daily spend produces unreliable A/B results. With low traffic, duplicate the product page and product, then send separate traffic to each [L0524.043].
  • Social proof and other conversion tactics should be tested once steady traffic arrives, so the page can be measured accurately [L1077.042].
  • Avoid site-wide changes such as theme swaps during the first two to four weeks of running ads (Source A 2022, older). Wait until a product page has a few hundred unique visitors before optimizing it, so you can tell what caused a change in conversion rate [L0803.053].
  • Do not change a checkout that still produces a good return on ad spend. If a test is needed, change one element at a time [L0963.058] (Source A 2022, older).
  • Conversion testing is a long-term process that needs time and learning, not a single app install. A small gain, such as moving from about 3% to 3.5% conversion, can represent a meaningful amount of money [L0390.014].
  • A realistic yield is about 8 tests per year. Of those, typically around 3 are confirmed as improvements. In the other cases, the current version was already the best option [L0390.010, L0390.011, L0423.014].
  • Best practices such as button color are not universal. The right choice depends on the business, audience and website, so test the option in your own store rather than copying others [L0390.007].
  • Conversion tests on real results can show gains of about 0.5 to 1 percent across more than 50 test variations [L1218.018].

Research and hypotheses

  • Good hypotheses come from real signals, such as customer feedback about something missing on a page, or a comparison of your unique selling proposition against competitors. Each hypothesis should name the exact problem it addresses [L1364.007].
  • Each hypothesis should be based on data or customer feedback collected so far [L0390.006].
  • Test a specific hypothesis about one change, for example "a bigger add-to-cart button will increase sales", instead of a broad goal such as "more sales" [L0390.006].
  • Use this template to write each hypothesis:
Hypothesis: If I change [specific element on a specific page], then [named metric, such as conversion rate or add-to-cart clicks] will [increase or decrease] because [customer reason based on feedback or data]. Write it down before the test starts so it can be checked against the result afterwards.

[L1364.006]

  • Each test needs a reason, so do not test changes without a basis. If you already have the lowest price in your market, testing a further price cut has little reason. Testing a price increase that keeps conversion stable can be worthwhile [L1364.028].
  • Research step before a test (Source B 2021-22, older):
    1. Collect the customer feedback behind the hypothesis.
    2. List the options for fixing the gap.
    3. Pull the current performance of the page for the same time period the test will run.
    4. Break that data down by traffic type, device type and demographics in Google Analytics. [L1364.008]
  • Session recordings (Lucky Orange or similar) show where customers drop off and what changes are needed [L0321.011].
  • Turn every insight from a page review into a conversion test. Change the flagged element, run the test and check whether results improve. Keep the six-factor checklist next to the workspace and run it for each page reviewed (Source B 2021-22, older) [L0473.030].

The CRO cycle

  • Run the CRO cycle in this order (Source B 2021-22, older) [L1364.005]:
    1. Form a hypothesis.
    2. Research it using customer feedback and current performance data.
    3. Document the planned test.
    4. Run the test.
    5. Document the results using the same metrics as the baseline.
    6. Analyze the results and write down the insight.
    7. Use the insight to form the next hypothesis and repeat the cycle. [L1364.005]
  • Write down ideas for future conversion tests in a tracking system before running any test. This keeps testing organized and makes clear what is planned, running and finished (Source B 2021-22, older) [L0399.005].

Choosing the test type

  • A/B test: Change one element and split traffic 50/50 between version A and version B, then implement the better version [L0390.008].
  • Split test: Compares two fundamentally different designs or page structures instead of one small detail [L0390.008].
  • Split test for solutions: Compares two distinct solutions, such as two brand or product options, to see which performs better [L423.008].
  • A/B testing (concept): Tests one element with two versions to check one specific hypothesis. Example: whether moving the add-to-cart button higher on the product page increases conversions [L423.007].
  • ABC test: Checks one hypothesis against three potential solutions, with traffic split across all variants. Example: which of three positions for a call-to-action button converts best [L390.009, L423.009].
  • Multivariate test: Combines several elements, such as 3 button sizes and 3 copy options, which gives 9 combinations and requires a much larger sample size. It is the most complicated method [L390.009, L423.010].
  • Note on the multivariate example: the unit's own example gives 9 combinations for 3 options and 2 variants. The stated rule (options multiplied by variants) gives 6 for those numbers. Check the count before using it [L423.010].
  • Simultaneous split (A/B), preferred: Show both versions at the same time to split traffic evenly. Comparing a page before and after a change can give false conclusions because of differences in weekday mix and traffic sources (Source B 2021-22, older) [L1364.014].
  • Consecutive test: Compares a fixed period before a change with a period after it, such as two four-week blocks. It is simpler to run but more exposed to other changes, so it is weaker than a split test, though still better than no testing (Source B 2021-22, older) [L1364.015].
  • Consecutive procedure (Source A 2019, older):
    1. Pick one element to test, such as a bonus offer or the button text.
    2. Run version A for one week with enough traffic.
    3. Run version B the following week and compare the results. Use this only when enough visitors come in, because time-based testing is less reliable [L356.042].
  • Page-builder split test (Source A 2019, older): Changes the content on the same URL and shows each variation to about 50 percent of visitors, instead of splitting URLs. Typical test items are offers, bonus items and button text [L356.043].
  • Setting up a simultaneous A/B test (Source B 2021-22, older) [L1364.016]:
    1. Create two identical versions of the page.
    2. Make only the planned change in one version.
    3. Use a tool that alternates visitors evenly between the two versions.
    4. Collect and compare the results for both versions at the end.
  • Use the tool to test a new Shopify theme against the current one before all traffic switches over. This shows whether the new theme converts better or worse first (Source B 2021-22, older) [L1364.049].

Keeping variables isolated

  • Test one single change at a time on a page, so any difference in results can be traced to that change. Testing several changes together makes results confusing (Source B 2021-22, older) [L1364.017].
  • Test one variable at a time. For example, test an offer by keeping the same creative and audience, then compare the conversion rate to the existing one [L1315.044].
  • When the target audience and angle are known, test one page element at a time. For example, test the headline first for about five days, then the product pictures, then the brag bar. Changing several elements at once makes results hard to attribute [L387.014].
  • Test several different marketing angles together only when the audiences and angles are truly different. Example: gaming, home decor and a therapeutic angle for the same product, to show which audience converts best without separate ads [L387.013, L387.014].
  • Group small changes into one concept when they belong to the same part of a page, such as the area around the add-to-cart button. Testing every combination of small elements one by one can take six months or more, which is too slow (Source B 2021-22, older) [L1364.018].
  • Example: If a product page has four elements around the add-to-cart button that may distract buyers, remove them together as one concept test. If the concept wins, refine it later rather than testing each element alone (Source B 2021-22, older) [L1364.019].
  • Never run two concept tests on the same page at the same time, for example a change to the add-to-cart area and a change to the product description. Concepts can run in parallel on different pages (Source B 2021-22, older) [L1364.020].
  • Stores with many product pages can run many tests at once, one per page. Stores selling one or two products have fewer pages to test in parallel, so testing is slower (Source B 2021-22, older) [L1364.021].
  • Verify that each variant is delivered correctly before reading the data. Split testing is technically demanding, and setup errors can easily invalidate results [L423.013].
  • Changing the price of the live store in Shopify is less reliable than split testing, because it compares two periods rather than two groups at the same time. Use split testing for prices [L999.067].

Setting up split tests and tools

  • Google Optimize, how it works: Turns one landing page URL into a single link that distributes visitors across several landing page variants according to set weights. Google reports how each variant performs [L387.010].
  • Weights: With three variants use 33 percent each. With two variants use 50 percent each. Any uneven split can be set to favor one variant [L387.011].
  • Google Optimize setup procedure (historic; the method still works with another tool):
    1. Create the page variants, one per angle or version you want to test.
    2. Open Google Optimize and set up a split test (A/B test).
    3. Add the variants and set the traffic weights (e.g., 33/33/33 for three variants, 50/50 for two).
    4. Copy the generated link and use it in ads, bio or organic posts.
    5. Read the performance data per variant to see which one converts best. [L387.012]
  • Google Optimize was shut down in September 2023, so it can no longer be used for weighted landing page split tests. The method still works with another split-testing tool: one link distributes visitors across several page variants by set weights, and results are compared per variant [L387.032].
  • Current tool: since Google Optimize was discontinued in 2023, use a current A/B testing tool for this procedure [L1260.067]:
    1. After optimizing the landing page, collect another 200 to 300 visitors and measure the funnel again.
    2. For a split test, send traffic 50/50 to two page versions, or 33/33/33 to three versions.
    3. Use a current A/B testing tool for this, since Google Optimize was discontinued in 2023. [L1260.067]
  • Historic procedure: Google Optimize (historic tool) can divert traffic 50/50 or 33/33/33 across three landing page variants. Check results after another 200 to 300 visitors [L1259.047].

  • Low-traffic tests must run longer to collect enough conversions [L1364.023].
  • Judge a test by whether the result is statistically significant, not by a rough impression. If there is no significant increase, the element may not have been a real problem. Keep the current version or test a different option (Source B 2021-22, older) [L1364.013].
  • A/B tests need a large amount of traffic to reach statistical significance [L524.043].

  • Products with little traffic or no sales history can need about eight weeks [L1364.047].

Significance and what counts as a win

  • A test counts as winning if it shows a positive improvement toward the stated hypothesis. A test with no change or a result going backwards counts as failed or inconclusive [L1364.043].
  • Use both checks: a winning test shows a positive improvement toward the hypothesis [L1364.043], and the result must be statistically significant to be trusted [L1364.013].
  • A test that shows no gain or a loss still has value, because it shows the hypothesis was wrong or incomplete [L1364.012].
  • A small change of about 1 to 2 percent is too small to trust [L999.022].

Traffic changes during a test

  • During a CRO test, avoid big changes to traffic, such as launching several new Google Shopping campaigns that send new traffic to the tested pages. Traffic changes make results useless because the conversion change can no longer be attributed to the page change (Source B 2021-22, older) [L1364.025].
  • Traffic targeting is cited as a large share of conversion outcomes, roughly 40% in the course framework. Natural shifts, such as growing organic search traffic and small pay-per-click adjustments, can be accepted without stopping the test (Source B 2021-22, older) [L1364.026].

Testing ads, offers and landing pages

Ad creatives

  • Test at least 3 different ad creatives for each product. Do not test fewer than 3 [L0280.013].
  • Allocate a minimum of $5 per day per creative. The ideal budget is $5 to $10 per day per creative, so $15 to $30 daily for 3 creatives [L0280.014].
  • Judge the landing page by its add-to-cart rate and judge creatives by CTR and CPC, so each asset is optimized on the metric that matches it [L871.028].
  • Testing optimization priority (Source C):
    1. Find the creative with a high CTR (1%+ on Facebook, high engagement rate on TikTok). This proves the ad is getting attention.
    2. Once the creative is locked, test offer variations (discount level, bundle structure, bundle price) to find the highest converter. Do not optimize both at the same time. Isolate variables [L307.028].

Offers

  • If testing different offers, maintain consistency first. Do not increase price mid-campaign because sales slowed. Lower the price back to the consistency baseline. Test one variable at a time. Kill offers that do not work. Keep and duplicate what works [L308.030].
  • Test campaign-level variants (Source C) [L1217.051]:
    1. Run a normal conversion campaign for about three days.
    2. Send one group of traffic to a collection page where each variant has its own listing.
    3. Send the other group of traffic to a single listing that holds all variants.
    4. Compare the results and keep the setup that performs better.
    5. Use a total test budget of about 20-50 USD. [L1217.051]

Landing pages

  • Build two landing pages for different buyer intents, such as a pre-selected starter kit and a full build-out. Send the campaigns to both pages. After about 10 days, see which page converts. Lean into the winning angle before testing gender-based angles [L1225.045].
  • Test the five first-view elements (Source C) [L916.023]:
    1. Create a version of the page with three features or elements in the first view.
    2. Create a second version with five features or elements in the first view.
    3. Run both versions in an A/B test and measure the conversion rate of each version.
    4. Keep the version with the higher conversion rate. [L916.023]
  • Test a GIF against a static image on the product page. The GIF may not convert better, so test it instead of assuming it works [L1194.026].

Test ideas list

Standing list

  • Build a standing list of test ideas covering offers, page structure and product page content. Add ideas as they come up. Start tracking tests from the beginning rather than postponing it (Source B 2021-22, older) [L1364.029].

Product page

  • Headlines: Run split tests on different headlines for the same product and compare time on page and conversion rate. Other copy elements can be tested the same way. Headlines should not be written once and never revisited (Source B 2021-22, older) [L0416.011].
  • Advertorial headlines: A headline test can show which headline grabs the most attention, for example a "10 reasons why" headline on a list-style advertorial followed by a sales page [L0999.068].
  • Testable page elements include product descriptions, product titles, product images, opt-in forms, product prices where pricing can be changed, collection page content, blog page layout, homepage layout and entire theme versions (Source B 2021-22, older) [L1364.027].
  • Product image emphasis: The three elements with the largest effect on conversion to test are images, headlines and colors. Focus tests on these before smaller changes [L570.008].
  • Customer reviews moved directly above the add-to-cart button: a testable concept. A suitable hypothesis is that this raises add-to-cart clicks and conversion rate, because shoppers see social proof at the moment they decide to buy (Source B 2021-22, older) [L1364.048].
  • Product page USP: A product page USP test can run for one month. Record the baseline beforehand and run no other test on that page during that month. If the new USP shows no significant gain, or converts worse than the original USP on the same page, the original is judged stronger, and the result is still recorded as an insight (Source B 2021-22, older) [L1364.050].
  • Button placement: Testing a button higher on the page is an example of A/B testing one element [L423.007].
  • Button color: Not universal; test in your own store [L390.007].
  • Product page layouts: Measure conversion rate after each layout change to see whether the new layout works [L1164.047].
  • Ebook cover designs: Test several cover designs for the same product to see which converts best, instead of committing to the first cover. Change only the cover between tests [L513.042].
  • Trust elements such as star ratings: Test one position at a time, for example lower on the page, directly under the product name, or next to the price. Keep the placement that converts best, because differences from a single element can be measurable [L1218.037].
  • Social proof and page improvements: test once steady traffic arrives [L1077.042].

Homepage and first view

  • Testing ideas for the first audit output: hero positioning, risk reversal and comparison modules. Label each as a test only when traffic supports it, otherwise as a fix [L886.021].
  • Five first-view elements: see the procedure in the section on ads, offers and landing pages [L916.023].

Offers, pricing and pop-ups

  • Discount values: A 5% discount is only a starting point. Edit the expiring coupon section over time and compare results, since 5% is not a proven best value [L1192.020].
  • Opt-in pop-up offers: Compare a pop-up offering 15% off the first order with one offering a free set of examples. The winning version is the one that earns more money, which can differ from the one with more sign-ups [L572.011].
  • Price changes: Testing a price increase that keeps conversion stable can be worthwhile. Testing a further price cut has little reason if you already have the lowest price in your market [L1364.028].
  • Pre-purchase return option (procedure) [L955.054]:
    1. Split incoming shoppers 50/50 and show the pre-purchase return option to only one group.
    2. Keep the other group on a normal cart and checkout with no return option.
    3. Run the test for about two weeks, recording checkout conversion, cart abandonment and AOV for both groups.
    4. If the option group does not lose conversion and AOV rises, test two fee levels such as $2.99 and $3.99 and compare uptake.
    5. Roll out the fee that gives the best uptake without a drop in conversion. [L955.054]
  • Postage-paid reply cards or envelopes: Test with and without them before you commit. The author found they rarely improve response enough to justify the cost [L1370.094].

Cart and checkout

  • Do not change a checkout that still produces a good return on ad spend [L963.058] (Source A 2022, older).
  • Exit-intent offer: Example of a candidate test to log as an idea. Replace an exit-intent offer of a percent-off discount code with a short product-finder quiz that routes visitors to the product type that suits them. Writing the idea into the changelog before testing it means it can be found again later, so it is not forgotten or retested blindly [L410.013].

Price testing

  • Use split testing for prices, not live price changes in Shopify [L999.067].

Analysis and deciding the winner

  • Analysis after a test (Source B 2021-22, older) [L1364.011]:
    1. Record the outcomes for the test period using the same metrics as the original baseline.
    2. Ask what changed and what it means.
    3. Ask what the result implies for the rest of the business and for future tests.
    4. Decide the next step: a new test, a refined version of the winner, or a move to another page element. [L1364.011]
  • Customer feedback that appears during the test is part of the result and can form a new hypothesis, such as the idea being right but the execution being wrong (Source B 2021-22, older) [L1364.012].
  • Decisions should wait for more data where possible, because the confidence score rises as the sample grows [L570.002].
  • For sales-based tests, the winner is the variant that earns more money, which can differ from the one with more sign-ups [L572.011].
  • Expected outcome: changing landing page elements based on testing produced conversion differences of about 0.5 to 1 percent across more than 50 test variations [L1218.018].

Documentation, changelogs and naming

  • Making unrecorded site changes on impulse makes it impossible to tell later whether a change helped, hurt or did nothing. Every change should be planned, recorded before it goes live and measured (Source B 2021-22, older) [L1364.001].

  • Document each test before it starts, covering (Source B 2021-22, older) [L1364.009]:

    • what is being tested,
    • the details of the change,
    • how the test will be implemented,
    • the baseline performance,
    • the planned start and end dates,
    • the duration.

    Keep the record in the same place as the results. [L1364.009]

  • Store every test record for as long as the business runs, not only until the test ends. Old records prevent repeating a failed test and can later inspire a modified test with new insight (Source B 2021-22, older) [L1364.010].

  • Changelog: Change tests every one to two weeks is a typical rhythm for active store owners, so a changelog becomes necessary early on. Log each change with its date and platform so that the many simultaneous tweaks can be separated later [L410.012].

  • Test naming: Name every Visually test with its device, scope, element and change, for example "mobile, site-wide, promo bar, text color" or "mobile BDP social proof". Clear names make the test report readable when several experiments run at the same time [L389.026].

Ongoing cadence

  • After a win is achieved and deployed, keep testing. Continue testing different recommendation ranking logic, design variations and customer segments to find further improvements beyond the initial test [L197.024].
  • Test conversion changes one at a time and expect a result over a fixed period, such as two weeks. Run each change long enough to measure a clear result before adding the next change, so the cause of any sales movement is identifiable [L410.011].
  • Change tests every one to two weeks is a typical rhythm for active store owners [L410.012].
  • Plan testing as a long-term effort. A realistic pace is about 1.5 months per test, which allows roughly 8 hypotheses over one year [L423.014].
  • Of about 8 hypotheses tested per year, typically around 3 are confirmed as improvements [L390.011].
  • Stores with many product pages can run many tests at once, one per page (Source B 2021-22, older) [L1364.021].
  • Never run two concept tests on the same page at the same time [L1364.020].
  • Do not change traffic sources during a test. Accept natural shifts only [L1364.025, L1364.026].
  • Do not run A/B tests with very small traffic. Focus on fixing obvious problems first [L390.012].
  • Keep a standing list of test ideas and add to it as they come up [L1364.029].

Set up a split test in Google Optimize:

  1. Create the page variants, one per angle or version you want to test.
  2. Open Google Optimize and set up a split test (A/B test).
  3. Add the variants and set the traffic weights (e.g., 33/33/33 for three variants, 50/50 for two).
  4. Copy the generated link and use it in ads, bio, or organic posts.
  5. Read the performance data per variant to see which one converts best. [L0387.012]

  • Testing completely different marketing angles in one split test (for example gaming, home decor, and a therapeutic angle for the same product) shows which audience converts best, without needing separate ads for each angle. [L0387.013]

  • When the target audience and angle are already known, test one element of the landing page at a time (for example the headline first for about five days, then the product pictures, then the brag bar), because changing several elements at once makes results hard to attribute. Only test multiple different angles together when the audiences and angles are truly different. [L0387.014]

  • ABC testing adds a third or further variant of the same element, for example three possible positions for the add-to-cart button, with traffic split across all variants. Multivariate testing combines several elements, such as 3 button sizes and 3 copy options, which means 9 combinations and a much larger sample size. [L0390.009]

  • Test conversion changes one at a time and expect a result over a fixed period, such as two weeks. Run changes long enough to measure a clear result before adding the next change, so the cause of any sales movement is identifiable. [L0410.011]

  • Change tests every one to two weeks is a typical rhythm for active store owners, so a changelog becomes necessary early on. Log each change with its date and platform so that the many simultaneous tweaks can be separated later. [L0410.012]

  • A candidate test worth logging as an idea is replacing an exit-intent offer of a percent-off discount code with a short product-finder quiz that routes visitors to the product type that suits them. Writing the idea into the changelog before testing it means it can be found again later, so it is not forgotten or retested blindly. [L0410.013]

  • A/B testing compares two versions of one element to check one specific hypothesis. For example, you could test whether moving the add-to-cart button higher on the product page increases conversions. [L0423.007]

  • Split testing compares two distinct solutions against each other to see which performs better. For example, two different brand or product options can be shown to visitors to find the stronger one. [L0423.008]

  • A/B/C testing checks one hypothesis against three potential solutions. For example, it can show which of three positions for a call-to-action button converts best. [L0423.009]

  • Multivariate testing examines a complex hypothesis that combines several variables, which makes it the most complicated method. The number of combinations equals options multiplied by variants: 3 options for 2 variants gives 9 combinations, and 3 size options with 3 copy options gives 9 combinations for one call-to-action. [L0423.010]

  • Each version in a test needs a sufficient sample, with the benchmark being about 10 samples per version. Results from smaller samples are unreliable. [L0423.012]

  • Running split tests is technically demanding, so setup errors can easily invalidate results. Verify that each variant is delivered correctly before reading the data. [L0423.013]

  • Test several ebook cover designs for the same product to see which one converts best, instead of committing to the first cover. Change only the cover between tests so the result shows which design performs. [L0513.042]

  • For an A/B test, aim for at least 1,000 samples per variant before treating the result as meaningful. In a 50/50 split this means 2,000 total recipients or visitors in the funnel, not 500 per variant. [L0570.001]

  • A result at 1,000 samples per variant can reverse once more data arrives, because small samples produce unstable winners. The confidence score rises as the sample grows, so decisions should wait for more data where possible. [L0570.002]

  • The three elements with the largest effect on conversion to test are images, headlines and colors. Focus tests on these before smaller changes. [L0570.008]

  • Declaring a winner after only 1,000 samples per variant risks choosing a version that loses once more data is collected. Wait for a larger sample before acting on a result. [L0570.012]

  • Split testing compares two versions of one element, such as an opt-in pop-up offering 15% off the first order versus one offering a free set of examples. The winning version is the one that earns more money, which can differ from the one with more sign-ups. [L0572.011]

  • Judge the landing page by its add-to-cart rate and judge creatives by CTR and CPC, so each asset is optimized on the metric that matches it. Use a sample of about 200 landing page visitors before judging a change. [L0871.028]

Test the five first-view elements:

  1. Create a version of the page with three features or elements in the first view.
  2. Create a second version with five features or elements in the first view.
  3. Run both versions in an A/B test and measure the conversion rate of each version.
  4. Keep the version with the higher conversion rate. [L0916.023]
    1. Split incoming shoppers 50/50 and show the pre-purchase return option to only one group. 2. Keep the other group on a normal cart and checkout with no return option. 3. Run the test for about two weeks, recording checkout conversion, cart abandonment and AOV for both groups. 4. If the option group does not lose conversion and AOV rises, test two fee levels such as $2.99 and $3.99 and compare uptake. 5. Roll out the fee that gives the best uptake without a drop in conversion. [L0955.054]

  • Price testing in Shopify by changing the price of the live store is less reliable than split testing, because it compares two periods rather than two groups at the same time. Use split testing for prices. [L0999.067]
